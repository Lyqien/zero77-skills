# 验收

1. 人物与文件数量：按关系分组；附属物归属正确，元歌与傀儡没有交换或融合。
2. 辨识：主要发型、配色、服装与道具完整；原图之外的补全须注明。
3. 比例：仍是小身体短四肢，元流男女视觉等高；坐姿、发饰、兽耳、羽翼不机械计入头身比。
4. 画法：与庄周 I、小乔 L 同一风格；大色块优先，局部切面密度可有差异，不强迫所有角色同样简略。
   眼睛专项：放大查看并对照 `images/erin.png`。虹膜是少量边界清楚的实色色块，没有白色高光点、玻璃反光、连续渐变或细密纹理；不因身体是多边形就忽略眼睛的动漫亮晶晶风格。保留角色眼睛色相及睁闭、眨眼、视线。发现跑偏时只针对眼睛修正。
5. 动作：检查肘膝、手腕、脚尖、握持与操控线；保留用户喜爱的动态，避免把自然等同于站姿。
6. 配色：色相忠于人物，饱和度柔和但不灰；小乔以 L 为锚点，允许不同角色冷暖不同。
7. 主体呈现：正常观看尺度下，人物及配件清楚，外围没有大面积、明显的模糊彩雾或光云。允许正常抗锯齿和不显眼的轻微轮廓过渡。不能把小范围半透明边缘或统计中的非零alpha判成不合格。保留主体白色色块。首次图通过这一视觉检查就直接保存，不自动去光雾、重生成或降为候选。只改眼睛时不顺便改alpha；确需去光雾时单独划定范围。
8. 规格：PNG、RGBA、1536x1024、3:2；完整入画、合理留白、版本命名清楚、不覆盖原版。
9. 保存行为：交付目录默认只有最终 PNG；不新建每图说明、提示词、生成记录等 Markdown、TXT 或 JSON。必要说明留在聊天中。仅用户明确要求时导出文档，不删除目录中用户已有的文件。技能自身 Markdown 说明文件正常保留。

RGBA 和 alpha 最小值零只证明有透明像素，不意味着无光雾；判断标准是肉眼可见的大面积模糊光雾，不是alpha是否存在半透明值；统计只能辅助，不能凭边缘过渡启动修图。文件规格统一也不要求所有人物拥有相同像素身高。

局部修改须对照用户选定底图检查未编辑区域。只改眼睛时，发束、武器、衣褶、切面、脸型、姿势、构图、画布和原有alpha不能变化；去光雾时，主体本身不能变化。非目标区域变动即不通过，保留原图，不把候选作为局部修改成功的成品。工具无实际遮罩或区域锁定能力时不承诺像素不变，失败后遵守修正次数上限，不用全图重生成掩盖限制。

有限样本已显示画风可以复用；细节、动作、补全设计与未来工具版本仍有随机性。用户对候选的确认与工具/助手的检查必须区分，不夸大稳定性。
